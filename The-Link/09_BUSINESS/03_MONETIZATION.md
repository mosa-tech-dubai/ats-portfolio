# Monetization

No monetization model or timeline has been decided. This file exists to record the one hard constraint already agreed on, and the open questions that remain.

## The Hard Constraint

**Any monetization must remain compatible with audience trust.** This is not a soft guideline — it is a filter every monetization idea must pass before being adopted. Use the Trust Check in `00_PROJECT_BIBLE/04_DECISION_PRINCIPLES.md`: "Would this erode the audience's trust in why we're really there?"

Concretely, this means:

- Sponsored content, if it ever exists, must be clearly disclosed and must still satisfy the Ad Test and Value Test — it cannot become a disguised advertisement.
- Guest businesses should never be able to pay for a more favorable episode, better placement, or editorial control over content.
- Any subscription, membership, or paid-tier model (if pursued) should add genuine additional value, not paywall basic honesty or gate community participation in a way that undermines `07_COMMUNITY/01_COMMUNITY_STRATEGY.md`.

## Open Questions — `TO BE DEVELOPED`

- Whether monetization happens at the show level (ads, sponsorships), the guest level (paid features — explicitly risky against the Trust Check and not recommended without careful design), the community level (memberships, events), or some combination.
- Timing — how much audience and trust needs to exist before introducing any commercial model.
- Which platforms' native monetization tools (if any) are used versus independent commercial arrangements.

## Next Step

Do not design a specific monetization mechanism until the pilot and initial episodes validate the format and audience response. Premature monetization risk is explicitly called out as incompatible with the "value before views" philosophy in `00_PROJECT_BIBLE/03_CORE_PHILOSOPHY.md`.
