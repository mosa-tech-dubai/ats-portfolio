# Live Format

## Status: Future, Not Launch-Required

Live interaction is a planned future layer of the ecosystem — it does not need to exist at launch or during the pilot phase. Do not build live infrastructure before the core recorded format is proven (`04_PILOT/`).

## The Intended Rhythm

Several recorded episodes accumulate community questions (`07_COMMUNITY/02_COMMENT_STRATEGY.md`) → a live episode features a guest (ideally a past guest, or a guest whose upcoming episode the community is anticipating) → real-time audience interaction resolves accumulated questions.

**Not every episode should be live.** Live is a periodic, special event layered on top of the core format, not a replacement cadence.

## What the Live Format Should Enable

- Real-time questions from the audience
- Direct guest interaction with the community, not just the host
- Open audience discussion
- Follow-up questions to points raised in earlier recorded episodes
- General community participation and visibility (e.g., recognizing recurring commenters)

## Open Questions — `TO BE DEVELOPED`

- Which platform(s) host live sessions
- Cadence (how many recorded episodes accumulate before a live is scheduled)
- Format length and structure for a live session
- How guests are selected/invited back for a live appearance
- Moderation approach for real-time audience interaction

## Next Step

Revisit this document once the pilot (`04_PILOT/`) has run and there's a real community large enough to make a live session meaningful — building this prematurely risks a live session with no audience to interact with, which undermines the format's whole purpose.
